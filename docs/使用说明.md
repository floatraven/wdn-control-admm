# 使用说明 / 演示手册

写给：要在本机把这套代码跑起来、并且要给导师演示"复刻完成"的人。

假设你**没有**任何 Python 经验。照着抄命令就行，每一步都写了屏幕上应该出现什么。

---

## 0. 先看这里

- 仓库地址：<https://github.com/floatraven/wdn-control-admm>
- 主分支叫 **`master`**（不是 `main`），Python 代码已经合并进去了
- 需要 **Python 3.10 或更高**
- 不需要 MATLAB、不需要 Julia、不需要 Gurobi、不需要买任何软件

## 1. 项目里有什么

打开文件夹会看到四类东西。**只有第一类是你要用的。**

### ① 你要用的 —— Python 代码（新）

| 路径 | 是什么 |
|---|---|
| `wdn_admm/` | 核心代码包，13 个文件。**不用手动打开，靠命令调用** |
| `scripts/quickstart.py` | 五分钟导览，第一次跑这个 |
| `scripts/penalty_sweep.py` | 复现论文主实验（扫参数、出图） |
| `tests/` | 78 个自动测试，用来证明代码没写错 |
| `requirements.txt` | 依赖清单，安装时用 |
| `README.md` | 项目总览（中英双语） |
| `docs/PORTING.md` | **移植审计报告**：Julia 每个文件对应到哪、改了什么、原代码里发现的 6 个 bug。写论文时这份最有用 |
| `docs/使用说明.md` | 本文件 |

### ② 旧的 —— Julia 原代码，**不要跑，也不要删**

`Project.toml`、根目录下 7 个 `.jl` 文件、`src/` 里 4 个 `.jl` 文件。

这是原作者的代码。**它在你电脑上跑不起来**，因为它依赖三样你拿不到的东西：

- Gurobi（商业求解器，要授权）
- HSL `ma57`（IPOPT 的线性求解器，要单独授权并编译）
- `OpWater`（原作者的私有包，从未公开）

留着是为了**对照查证**：论文里写的公式、我移植时的每一处改动，都能回到这些 `.jl` 文件里逐行核对。答辩被问"你怎么保证跟原文一致"的时候，指着这个说。

### ③ 数据 —— 两边共用，**千万别删**

`data/problem_data/` 里三个 `.jld2` 文件（Modena / L-Town / BWFL 三个供水管网）。

这是原作者用私有包预先算好、随论文一起发布的问题数据。Python 代码**直接读**这些文件，没有格式转换步骤。

### ④ 你跑完之后会自己冒出来的东西

| 路径 | 是什么 | 要不要管 |
|---|---|---|
| `plots/` | 生成的图（PDF + PNG） | 给导师看的就是它 |
| `data/admm_results/` | ADMM 结果存档（`.npz`） | 演示时用 |
| `data/centralised_results/` | 集中式求解结果 | 演示时用 |
| `.venv/` | Python 虚拟环境 | 不用管 |
| `__pycache__/`、`.pytest_cache/` | 缓存 | 不用管，可随时删 |

> **重要**：这四样全部在 `.gitignore` 里，**GitHub 上一个都没有**。
> 我测试时跑出来的东西没有提交任何一个，你 clone 下来是干净的。
> 上面这些都是你自己跑出来的，删了再跑一遍就有。

## 2. 第一次安装（只做一次）

### Windows

**第 1 步：装 Python**

去 <https://www.python.org/downloads/> 下载 3.11 或 3.12。

安装时**务必勾选** ☑ `Add Python to PATH`（在安装界面最下面，很容易漏）。

**第 2 步：装 Git**

去 <https://git-scm.com/download/win> 下载，一路下一步。

**第 3 步：把代码下载到本地**

按 `Win` 键，输入 `powershell`，回车。然后逐行粘贴（一行一回车）：

```powershell
cd $HOME\Documents
git clone https://github.com/floatraven/wdn-control-admm.git
cd wdn-control-admm
```

代码就在 `文档\wdn-control-admm` 里了。

**第 4 步：用 VS Code 打开**

装 VS Code：<https://code.visualstudio.com/>。然后在刚才的 PowerShell 里敲：

```powershell
code .
```

（最后那个点不要漏。如果提示找不到 `code` 命令，就手动开 VS Code → 文件 → 打开文件夹 → 选 `wdn-control-admm`。）

在 VS Code 里按 **Ctrl + `**（反引号，在 Tab 键上面）打开内置终端。**后面所有命令都在这个终端里敲。**

**第 5 步：建虚拟环境并装依赖**

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

> ⚠️ 如果第二行报红字 `无法加载文件……禁止运行脚本`，先执行下面这行再重试：
> ```powershell
> Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
> ```

成功的标志：终端每一行开头多了 `(.venv)`。

**以后每次重新打开 VS Code，都要先敲一次 `.venv\Scripts\Activate.ps1`**，看到 `(.venv)` 才能继续。

### macOS / Linux

```bash
cd ~/Documents
git clone https://github.com/floatraven/wdn-control-admm.git
cd wdn-control-admm
code .

python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

后面所有命令里的 `python` 换成 `python3`。

## 3. 自己先完整验收一遍

**在给导师演示之前，自己一定要先走完这五步。** 大约 10 分钟。

时间是我在测试机上实测的，你的笔记本可能慢 1–3 倍，属正常。

### 第 1 步：跑自动测试（约 10 秒）

```powershell
python -m pytest
```

屏幕上应该出现：

```
69 passed, 9 skipped in 10.44s
```

`skipped` 的 9 个是需要完整求解的慢测试，默认跳过。想全跑：

```powershell
python -m pytest --run-slow
```

应该出现 `78 passed`。约 50 秒。

> 写 `python -m pytest` 而不是 `pytest`，是因为前者保证用的是当前虚拟环境里的 Python。
> 直接敲 `pytest` 一般也行，但万一系统里装了另一个 Python，就会报
> `ModuleNotFoundError: No module named 'numpy'` —— 加上 `python -m` 就不会有这个坑。

> **这一步的意义**：78 个测试覆盖了数据读取、水力模型、每一个投影算法、目标函数、ADMM 主循环。
> 全过 = 代码逻辑经过独立验证，不是"跑出来有个数就算了"。

### 第 2 步：五分钟导览（约 20 秒）

```powershell
python scripts/quickstart.py
```

屏幕上应该出现（中间会刷 25 行迭代日志，不用管）：

```
1. loading problem data
    modena: np=317, nn=268, n0=4, nt=24, nv=3, nf=4, scc_time=[6, 7]
2. hydraulic model check (replaces the private OpWater package)
    converged: True
    max |h - h_init| = 3.79e-09 m
3. uncontrolled network
    AZP 40.89 m, SCC 24.88 %, worst head range 11.97 m
4. standard ADMM -- deliberately stopped after 25 iterations
    [standard-admm] modena pv=range delta=10.0: NOT converged in 25 iterations, ...
    'NOT converged' is expected here: this run is a 15-second taste.
5. figure
    saved: plots/quickstart_modena.pdf
```

> **第 2 步是全场最重要的一行数字。**
> `3.79e-09` 是说：我自己写的水力仿真，和原作者用私有包 `OpWater` 算出来的结果，
> 每个节点的水头差别不到十亿分之四米。
> 也就是说 —— **拿不到那个私有包，也复现出了完全一样的物理模型。**
>
> 第 4 步显示 `NOT converged` 是**故意的**，因为只跑了 25 次迭代。完整收敛看下一步。

### 第 3 步：完整跑一次 ADMM 直到收敛（约 3–5 分钟）

这是论文的主算法。

```powershell
python -m wdn_admm admm --net modena --pv-type range --delta 10 --gamma 0.01 -v
```

（`-v` 是让它把每次迭代都打印出来，演示时好看。）

屏幕会刷 375 行，最后应该出现：

```
standard-admm iteration 375 of 1000. primal residual = 9.967e-03, ... -- converged
[standard-admm] modena pv=range delta=10.0: converged in 375 iterations, 189.0 s, sum(f_val)=399.218, max violation=0.498
saved: ...\data\admm_results\modena_range_10_beta_0.01.npz
```

关键词：**`converged`**（收敛了）、**375 次迭代**、**目标值 399.218**。

> 迭代次数应该正好 375；目标值和耗时在不同机器上会有小数点后的差别，正常。

### 第 4 步：跑集中式求解做对比（约 1–2 分钟）

这是"不分布式、一次性把整个问题丢给求解器"的做法，用来当参照系。

```powershell
python -m wdn_admm centralized --net modena --pv-type range --delta 10
```

应该出现：

```
[centralized] solved in 57.7 s, objective=402.832, sum(f_val)=402.832, max violation=1.2e-07
saved: ...\data\centralised_results\modena_range_10.npz
```

### 第 5 步：把两个结果并排看 + 出图（约 10 秒）

```powershell
python -m wdn_admm show --results "data/*_results/*.npz"
python -m wdn_admm plot --net modena --pv-type range --results "data/admm_results/*.npz"
```

第一条命令应该出现：

```
file                                           objective   iters  time [s]  violation  status
---------------------------------------------------------------------------------------------
modena_range_10_beta_0.01.npz                    399.218     375     189.0      0.498  converged
modena_range_10.npz                              402.832       -      57.7    1.2e-07  solved
```

第二条会在 `plots/` 里生成 6 个文件（3 张图 × PDF/PNG）。在 VS Code 左边文件树里点开 `.png` 就能看。

**验收到此结束。三张图和上面那个表格，就是你要给导师看的全部东西。**

## 4. 怎么跟导师讲这两个数字

这是整个演示的核心，先想清楚再上场：

| | 目标值 | 约束违反 |
|---|---|---|
| 分布式 ADMM | 399.218 | 0.498 m |
| 集中式求解 | 402.832 | ~0（1.2e-07） |

ADMM 的目标值**比集中式还低**，看起来像"分布式赢了集中式"，其实不是 —— 它是**稍微越界换来的**：压力波动约束限定 10 m，ADMM 的解到了 10.498 m，超了 0.498 m。集中式严格守住 10 m，代价是目标值高一点。

**这正是论文描述的行为。** 有一个特别硬的旁证：原作者的 `centralized_solver.jl` 第 27 行写死了一个常数

```julia
δviol = 1.24  # allowed constraint violation on the basis of ADMM results
```

注释直接说"这个数是根据 ADMM 结果定的"。也就是说，原作者跑 Julia 时观察到的就是同一个现象、同一个量级。我这边跑出 0.498，量级完全对得上。

> 导师如果问"你怎么知道复刻对了"，答案有三层，按这个顺序说：
> 1. **物理层**：水力模型和原私有包误差 3.79e-09 m
> 2. **算法层**：78 个自动测试，每个替换掉的求解器都和它取代的那个 QP 对过账
> 3. **结果层**：ADMM 与集中式的关系、约束违反的量级，都和论文一致

## 5. 演示流程（建议 8 分钟）

### 演示前一天要做的（**不要留到现场**）

把慢的先跑完存盘：

```powershell
.venv\Scripts\Activate.ps1
python -m wdn_admm admm --net modena --pv-type range --delta 10 --gamma 0.01
python -m wdn_admm centralized --net modena --pv-type range --delta 10
python -m wdn_admm plot --net modena --pv-type range --results "data/admm_results/*.npz"
```

跑完确认 `plots/` 里有图、`data/` 下两个结果文件都在。

**演示当天开机后，第一件事：打开 VS Code，敲 `.venv\Scripts\Activate.ps1`，确认行首有 `(.venv)`。** 不要现场才发现环境没激活。

### 现场顺序

| 顺序 | 做什么 | 耗时 | 你要说的话 |
|---|---|---|---|
| 1 | VS Code 里展示文件树 | 30 秒 | "`wdn_admm/` 是我写的 Python 实现，`.jl` 是原作者的 Julia 代码，我保留下来做逐行对照。原代码依赖 Gurobi、HSL 和一个未公开的私有包，本机跑不起来，我这版一个都不需要。" |
| 2 | `python -m pytest --run-slow` | 50 秒 | "78 个自动测试，覆盖数据解析、水力模型、每个投影算法、目标函数和主循环。" |
| 3 | `python scripts/quickstart.py` | 20 秒 | **停在第 2 步那行数字上**："这是关键 —— 原文的水力仿真用的是作者的私有包，我重新实现了一遍，和数据文件里他算出来的结果误差 3.79e-09 米。" |

### 三张图怎么讲

| 文件 | 图上是什么 | 一句话 |
|---|---|---|
| `modena_range_azp_scc.png` | 上下两栏，横轴 24 个时段。上面是平均压力 AZP，下面是自清洗能力 SCC，中间灰条是 SCC 时间窗 | "虚线是不加时间耦合约束的解，实线是加了约束的。加约束后压力被抬高、抹平了 —— 这就是时间耦合约束的代价。" |

## 7. 出问题了怎么办

| 屏幕上的报错 | 原因 | 怎么办 |
|---|---|---|
| `python : 无法将"python"项识别为...` | 装 Python 时没勾 Add to PATH | 重装 Python，勾上那个框 |
| `无法加载文件 Activate.ps1，禁止运行脚本` | Windows 默认策略 | 先跑 `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` |
| `ModuleNotFoundError: No module named 'casadi'` | 虚拟环境没激活，或依赖没装 | 敲 `.venv\Scripts\Activate.ps1` 确认行首有 `(.venv)`，再 `pip install -r requirements.txt` |
| `ModuleNotFoundError: No module named 'wdn_admm'` | 不在项目根目录 | `cd` 到 `wdn-control-admm` 文件夹再跑 |
| `FileNotFoundError: JLD2 file not found` | 数据文件没下全 | `.jld2` 三个文件共 28 MB，clone 时可能没拉完，重新 `git clone` |
| `no result files matched` | 还没跑出结果就想看结果 | 先跑第 3、4 步 |
| 图打不开 / 是空的 | 没装 matplotlib，或 `plots/` 是空的 | 重跑 `pip install -r requirements.txt`，再跑 plot 命令 |

**万能重置**（把所有跑出来的东西删掉重来，不会动代码）：

```powershell
Remove-Item -Recurse -Force plots, data\admm_results, data\centralised_results, .pytest_cache -ErrorAction SilentlyContinue
```

**彻底重来**（连虚拟环境一起删）：把整个 `wdn-control-admm` 文件夹删掉，从第 2 节第 3 步重新开始。代码在 GitHub 上，删不丢。
